# Environments harness: old implementation and web-tool research

Source inspection, 2026-09-05. This note records the checked-in implementations, not claims about current hosted behavior. No gateway calls or implementation changes were made. Recommendations are separated from source facts.

## Old harness: verified facts

The old harness is an environment-building agent: discover project environments and execution targets; prepare a persistent machine directory or create a temporary sandbox, configure it, snapshot it, and register a reusable environment. It can also update existing environments. Its system prompt distinguishes machine identity/state from reproducible sandbox filesystem state, asks when target/account selection is ambiguous, avoids duplicates, and requires verification before registration. [System prompt](/Users/notacoder/Desktop/harnesses/agent-pane/apps/environment-harness/src/harness/system_prompt.rs:1)

Configuration fields are `provider: string`, `model_id: string`, `reasoning_level: string`, optional `account_id: UUID`, required `project_id: UUID`, and `web_search_enabled: boolean` defaulting to true. Camel-case aliases exist for the last five names where applicable. Configuration has no fixed machine target; every filesystem call selects a machine. The old model resolver uses a fixed model catalog and handles compaction-specific options. Those are old implementation facts, not requirements for the new harness. [Config](/Users/notacoder/Desktop/harnesses/agent-pane/apps/environment-harness/src/runtime/config.rs:6), [resolver](/Users/notacoder/Desktop/harnesses/agent-pane/apps/environment-harness/src/harness/model_resolver.rs:39)

## Existing web packages: verified facts and portability issues

Both packages are independent Rust libraries backed directly by Firecrawl, not the execution gateway. They offer typed `execute`, argument parsing, model-facing `definition`, injectable HTTP client/endpoint, and text plus structured details. They depend on `dotenvy`, `llm-contracts`, `reqwest`, `serde`, `serde_json`, `thiserror`, and `url`. [Search manifest](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/search/Cargo.toml:1), [scrape manifest](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/scrape/Cargo.toml:1)

Search sends `/v2/search`: ten results, web source only, safe mode, URL filtering, highlights, 30-second service timeout and 35-second HTTP timeout. It formats titles, URLs, descriptions and warning, and retains results/search ID/credit usage in details. The model cannot change these options. [Constants](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/search/src/lib.rs:16), [request/output](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/search/src/lib.rs:238)

Scrape sends `/v2/scrape`: Markdown, main content, PDF parser, one-hour cache max age, 60-second service timeout/65-second HTTP timeout, base64 image removal, ad blocking, automatic proxy, cache storage. It accepts HTTP(S) URLs with a host and no embedded credentials. Markdown is bounded approximately to 50 KiB (40 KiB head + 10 KiB tail + marker), with source/title/warnings added outside that bound. PDF page fragments are combined when the top-level Markdown is missing. [Request](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/scrape/src/lib.rs:243), [URL validation](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/scrape/src/lib.rs:354), [formatting/truncation](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/scrape/src/lib.rs:401)

Porting issues visible in source:

1. The old packages' workspace `llm-contracts` resolves to `packages/llm-contracts`, whereas Platform uses `llm/packages/llm-contracts`. Directly importing old packages retains the wrong contract dependency. Port their small implementation/adapt types rather than assuming identically named Rust types are interchangeable. [Old manifest](/Users/notacoder/Desktop/harnesses/agent-pane/Cargo.toml:47), [Platform manifest](/Users/notacoder/Desktop/harnesses/agent-pane/platform/Cargo.toml:24)
2. `from_package_env` loads a `.env` path built from compile-time `CARGO_MANIFEST_DIR`. Deployment should instead inject worker-managed credentials/clients. Both context structs derive `Debug` while containing raw API-key strings: redact those in the port. [Search context](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/search/src/lib.rs:37), [scrape context](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/scrape/src/lib.rs:41)
3. Both check Content-Length before reading, then call `.bytes()` and check size afterward (2 MiB search, 16 MiB scrape). Missing/inaccurate Content-Length therefore permits buffering beyond the intended cap. Read chunks with a cumulative bound. [Search response](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/search/src/lib.rs:260), [scrape response](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/scrape/src/lib.rs:269)
4. Search has no separate model-output cap and repeats data in text/details. Scrape bounds Markdown but not title/warnings/other metadata. Add an end-to-end serialized tool-result limit compatible with Platform commits, especially with no compaction. [Search output](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/search/src/lib.rs:289), [scrape output](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/scrape/src/lib.rs:420)
5. The execute APIs have no operation context, cancellation parameter, durable request ID or recovery lookup. They make one HTTP request without a retry loop. Worker cancellation can drop the future but does not promise cancelling accepted Firecrawl work; recovery may repeat a billable request. [Search execution](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/search/src/lib.rs:238), [scrape execution](/Users/notacoder/Desktop/harnesses/agent-pane/packages/tools/firecrawl/scrape/src/lib.rs:243)

## Recommendations for the new harness (not implemented decisions)

- Keep the environment-builder role/workflows, concise research tools, project-bound registration, verification before snapshotting, and ambiguity handling. Use the new basic harness loop/reasoning support rather than copying old broker runtime, catalog allowlist or compaction.
- Add explicit `host_id` and registered `workspace_root_id` to each filesystem-tool wrapper, preserving the new packages' `file_path`, exact single-edit schema and millisecond Bash timeout. Default relative filesystem paths to that selected root. This allows one run to configure multiple targets and fixes the old one-root assumption without introducing a mutable global target-switch tool.
- Bind project scope in config (or validated session metadata), not in model arguments. Confirm whether “all environments” means current project or global inventory; the old implementation was project-scoped.
- Unify environment registration around the current `machine`/`sandbox` record concept. Do not blindly port the old template name, `setup_script`, update tool, automatic-inactivity-cleanup claim, or sole-root restriction. These require independent confirmation against the new Platform/execution APIs.
- Reuse `search(query)` and `scrape(url)` shapes with worker-side Firecrawl credentials. Treat fetched content as data, not instructions; preserve source URLs. No compaction increases the importance of bounded web outputs.
- Avoid a default fixed execution host in harness configuration: target discovery and sandbox creation supply targets during the run. Persist resolved targets alongside pending operations so worker recovery cannot accidentally execute on a newly selected host/root.

## Current integration findings

- The current run already carries `project_id`; derive tool scope from this authoritative context instead of accepting a second project identifier in config. The current environment list is project-scoped and unpaginated. [Run](/Users/notacoder/Desktop/harnesses/agent-pane/platform/packages/platform-runtime-contracts/src/records.rs:20), [list](/Users/notacoder/Desktop/harnesses/agent-pane/platform/apps/server/src/projects/environments/service.rs:32)
- Environment creation currently generates a fresh ID for every POST. Add a lease-scoped, idempotent runtime command before using it as a recoverable agent tool; a lost HTTP response must not cause duplicate records. Current runtime-client queries and commands do not expose environment operations. [Create](/Users/notacoder/Desktop/harnesses/agent-pane/platform/apps/server/src/projects/environments/service.rs:51), [runtime client](/Users/notacoder/Desktop/harnesses/agent-pane/platform/packages/platform-runtime-client/src/lib.rs:225)
- Machine records validate a registered, non-deleted host and a known root, but not a live connection or directory existence. Sandbox records require a ready snapshot; snapshot records do not advertise roots, so the server currently stores a null native root path and cannot validate that root/path. The harness must verify the directory while the source sandbox is accessible. If native sandbox root paths should appear in the dashboard, extend the snapshot metadata contract separately. [Validation](/Users/notacoder/Desktop/harnesses/agent-pane/platform/apps/server/src/projects/environments/gateway.rs:62)
- Gateway sandbox creation takes a tagged source: `base` with optional `e2b_account_id`, or `snapshot` with a logical gateway `snapshot_id`. Restoration inherits the snapshot account. Base means the gateway-configured supervisor-enabled template, not any arbitrary provider template. Creation returns an asynchronous resource; wait for readiness and a live descriptor before filesystem calls. The gateway default lifetime is 3,600 seconds, configurable, and explicit lifetimes must be 1–86,400 seconds. [Create](/Users/notacoder/Desktop/harnesses/agent-pane/execution/apps/execution-gateway/src/http.rs:753), [default](/Users/notacoder/Desktop/harnesses/agent-pane/execution/apps/execution-gateway/src/config.rs:43)
- Snapshot completion marks the source host paused. Expose this in the tool result; a separate resume tool supports further inspection without implicitly starting paid compute. [Completion](/Users/notacoder/Desktop/harnesses/agent-pane/execution/apps/execution-gateway/src/database.rs:1210)
- Snapshot retry issue: HTTP creation checks the host is ready before invoking the database's idempotency lookup. If the first request succeeded and its response was lost, retry after snapshot completion fails because the source is now paused. Resolve an existing same-key/same-body receipt before mutable-state checks, retaining validation for genuinely new requests. [HTTP](/Users/notacoder/Desktop/harnesses/agent-pane/execution/apps/execution-gateway/src/http.rs:1096), [database replay](/Users/notacoder/Desktop/harnesses/agent-pane/execution/apps/execution-gateway/src/database.rs:1008)
- Execution-client currently connects to ready hosts for execution operations; it does not provision or resume them. Add a typed gateway management surface rather than repeating raw HTTP in each tool. [Client](/Users/notacoder/Desktop/harnesses/agent-pane/execution/packages/execution-client/src/client.rs:54)

### Proposed first version

Keep model/reasoning/LLM-account configuration and provider policy from the basic harness, without a required execution target. Keep four filesystem tools, wrapping their schemas with `host_id` and `workspace_root` (the registered root ID, matching existing config/record naming). Relative paths start at that root; Bash retains optional `workdir`. Include `search`, `scrape`, `list_environments`, a combined `list_execution_resources`, `list_snapshots`, `create_sandbox`, `snapshot_sandbox`, `resume_sandbox`, and `create_environment`: 13 tools total. These are proposals, not implemented contracts.

Keep sequential execution, full session history, no compaction, and the basic harness's steering/abort/recovery behavior. Key read observations by resolved host/root/path and consume them after mutations. Persist lifecycle request identity before effects and resource IDs before polling. Keep credentials in worker configuration and provenance in harness-supplied metadata, never model arguments. Bounded web output and chunked setup commands matter: the current basic Bash tool has a 10-minute maximum and no interactive/background mode. Do not silently increase that shared tool limit.

Do not initially port update/delete-environment tools or setup scripts. Do not assume a completed environment record cleans up live resources. Snapshot completion already pauses the builder; abort before that may leave a sandbox running until its configured lifetime. Explicit cleanup policy can be added without changing what an environment record means.
